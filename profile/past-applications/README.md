# Past applications

The user's own previously submitted applications, kept as source material.
Their own copies of their own writing, which is allowed (PRD §14, red line 4).

**What these are for.** Two things:

1. **Evidence provenance.** Entries in `evidence-bank.md` that were mined from
   these documents cite the file in their `source:` field. The claim is the
   user's own prior sworn-to account of their work, not a model's inference.
2. **Voice reference.** These show how the user actually writes an application
   in the Australian community and public sector register. `voice.md` remains
   the tone spec; these are worked examples of it.

**Dates matter.** Each file is named for the year it was written. The 2024
documents describe roughly the first two years at ACON and are silent on
everything since. Treat an absence in them as "not yet written down", never as
"did not happen".

| File | Written | What it is |
| --- | --- | --- |
| `2022-acon-gbq-mens-officer-selection-criteria.txt` | ~2022 | Ten selection criteria responses, applying into ACON. Pre-dates the ACON role, so its evidence is research assistant, BlaQ, YCollab, AEC and Coles. |
| `2024-selection-criteria-response.txt` | ~2024 | Seven criteria responses, ~1¾ years into ACON. The densest single source of ACON duties. |
| `2024-ahrc-project-support-officer-cover-letter.txt` | ~2024 | Cover letter, Project Support Officer (Community Support), Australian Human Rights Commission. Narrative form. |

**Caution when mining these.** They are persuasive documents, written to a
brief. A phrase like "advanced time management skills" is a self-assessment,
not an accomplishment, and does not become an evidence entry. Mine the
*specifics* — a named system, a named forum, a counted thing, a named
deliverable — and leave the adjectives behind.
